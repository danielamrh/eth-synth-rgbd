# synthrgbd: synthetic RGB-D of aluminium parts with a realistic depth camera model

Code for the ETH Zurich technical assignment (doctoral researcher in humanoid robotics, 3D perception
and embodied AI). The question: does a realistic model of the Intel RealSense D435 change the outcome
of a downstream grasping step compared with ideal depth, and do simpler noise models predict that change?

Pipeline: MuJoCo renders an ideal *G-buffer* (RGB, z-depth, instance and material ids, normals,
intrinsics, pose). A composable sensor model turns ideal depth into the depth the D435 would report,
with every effect switchable for ablations. A simple depth-based planner picks a part, and the grasp
is executed physically in MuJoCo.

**Main result** (300 paired scenes): with 6 mm gripper clearance per side, the D435 model lowers grasp
success from 94.7 % to 87.3 % (p = 0.001); with 12 mm the loss is 2.0 pp and not significant.
Amplitude-matched Gaussian noise behaves like ideal depth, Dex-Net 2.0 noise is far too pessimistic.

## Setup

Tested with Python 3.11 on Windows 11.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate   Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
pytest                           # unit tests
```

On Linux the renderer uses headless EGL (`MUJOCO_GL=egl`). On Windows and macOS
MuJoCo's default OpenGL backend is used.

Quick look at the sensor model:

```bash
python scripts/probe_render.py   # renders the probe scene to figures/probe.png
python scripts/demo_sensor.py    # ideal vs simulated D435 depth, one panel per effect
```

## Reproducing the report

Results and figures are not stored in the repository; every number in the report is regenerated by
the commands below. Seeds are fixed.

### Calibration on real metal parts (report Sections 2.2 and 3.3, Table 3)

The metal and edge effects are calibrated on real RealSense D415 depth of metal parts from
ROBI (Yang et al., 2021, CC BY-NC-SA 4.0). The data is not redistributed here; the fetch script
pulls only one scene (~60 MB) out of the 3.7 GB archive via HTTP range requests.

```bash
python scripts/robi_fetch.py --object Zigzag --scene 4         # calibration scene
python scripts/robi_fetch.py --object Zigzag --scene 5         # holdout scene
python scripts/robi_d415_metal.py --object Zigzag --scene 4    # dropout/bias vs angle, ~10 min
python scripts/robi_blob_size.py --scene 4                     # dropout blob size (corr_px)
python scripts/robi_edge_steps.py --scene 4 --step 2           # edge dropout vs depth step
python scripts/robi_d415_metal.py --object Zigzag --scene 5
python scripts/robi_d415_metal.py --object Zigzag --scene 5 --simulate
python scripts/robi_compare.py                                 # holdout check: model vs real scene 5
python scripts/robi_grasp_check.py --scene 5                   # planner on real vs simulated depth, ~6 min
```

The measured values are already in `configs/camera_d435.yaml`, each with its source, so the grasp
experiment does not need the ROBI data.

### Grasp experiment (report Sections 3.2 to 3.4, Table 2)

Procedural cells (3-6 aluminium profiles and L-brackets, settled by physics, D435 on a randomised
fixed mount). Each scene is rendered once; every sensor condition (ideal, full D435 model,
D435 minus one effect, simpler noise models from the literature, metal sensitivity) is applied to
the same G-buffer, a top-down grasp is planned from depth and executed with a parallel-jaw gripper
in MuJoCo from the same settled state. Labels (part class, 6D pose, instance masks) and RGB-D of
the first 20 scenes are stored in `results/grasp/<tag>/examples/`.

```bash
python scripts/grasp_experiment.py --tag main                          # 12 mm clearance, ~25 min on 6 cores
python scripts/grasp_experiment.py --tag clear6mm --clearance 0.006    # 6 mm clearance
python scripts/grasp_report.py --tag main                              # Table 2, results/grasp/main/summary.json
python scripts/grasp_report.py --tag clear6mm
python scripts/grasp_camera_pose.py --tag main                         # Section 3.4: gap vs camera distance and tilt
python scripts/grasp_camera_pose.py --tag clear6mm
python scripts/grasp_sensitivity.py --tag main                         # Section 3.4: sensitivity tornado plot
python scripts/grasp_sensitivity.py --tag clear6mm
```

### Video

`videos/grasp_clear6mm.mp4` shows three scenes where the grasp from ideal depth lifts the part and
the grasp from D435 depth fails, with the depth image each planner saw. To regenerate it:

```bash
pip install -e ".[video]"
python scripts/grasp_video.py --tag clear6mm --n 3
```

## Layout

| Path | Content |
|------|---------|
| `configs/camera_d435.yaml` | camera model, every parameter with its source or measurement |
| `configs/noise_baselines.yaml` | simpler noise models (i.i.d., z²-Gaussian, Dex-Net 2.0) |
| `configs/grasp_experiment.yaml` | conditions, scene count, planner and gripper settings |
| `src/synthrgbd/render/` | MuJoCo to `GBuffer` |
| `src/synthrgbd/sensor/` | `SensorModel` pipeline and effects (`effect(depth, gbuf, params, rng) -> depth`, 0 = invalid) |
| `src/synthrgbd/scene/` | MJCF scene construction (`cell.py`: procedural cells, gripper, labels) |
| `src/synthrgbd/perception/` | depth-based grasp planner |
| `src/synthrgbd/eval/` | grasp execution in MuJoCo |
| `scripts/` | one entry point per step |
| `tests/` | unit tests for effects, sensor, renderer and gripper |
| `videos/` | grasp video |
